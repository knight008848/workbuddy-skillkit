# 验收标准（bilingual-subtitle）

交付前跑 `python scripts/verify.py`，下面的每一项都对应脚本里的一个检查。
不通过就返工，不要「看着差不多」就交。

## 硬性项（不通过 = 不可交付）

| 检查 | 判据 | 不通过怎么办 |
| --- | --- | --- |
| 双语结构 | ≥ 90% 条目同时含中文和拉丁字母 | `segments.py merge` 时漏了译文，或之后被人手改坏了，检查 dst.json 覆盖是否完整 |
| 时长为正 | 每条 `end > start` | 时间轴损坏，回退到重新转写 |
| 时间轴无重叠 | 前条 end ≤ 后条 start | 分片拼接顺序错，用 `segments.py concat` 而不是 `cat` |
| 末条不越界 | 末条 end ≤ 成片时长 + 1s | 合成时被截断，检查 ffmpeg 合成日志 |
| 无乱码 | 文件不含替换字符 | 编码问题，重写为 UTF-8 |
| 成片时长一致 | 与原片差 ≤ 0.5s | 合成参数错了，重合成 |

## 软性项（告警，需人判断）

| 检查 | 判据 | 说明 |
| --- | --- | --- |
| 中文行宽 | 每行 ≤ 18 字 | 超了会换行溢出，重译更短，或调 `--max-cjk` |
| 英文行宽 | 每行 ≤ 12 词 | 同上，用 `--max-english` 调整 |
| 首条时间 | ≤ 10s | 太晚说明开头有长静音，确认是否漏内容 |
| srt 编码 | 带 BOM | 不带 BOM 在部分 Windows 播放器会乱码 |
| 英文大小写 | 首字母大写、`i` 已改为 `I`、句末有标点 | 转写普遍全小写，`merge --normalize-en` 修；专有名词仍要人确认 |
| 断句密度 | 每条停留 1–4 秒 | `segments.py audit` 列碎片与过长，见 recipes 第 11 节 |

## 人工抽检（脚本查不出来的）

1. **同步性**：抽开头、中间、结尾各 2 条，比对口型与字幕，误差应 < 0.3 秒
2. **术语一致**：术语表里的词逐个全片搜一遍，确认没有第二种译法
3. **语义完整**：中文不要为凑长度删信息；宁可让字幕多停 0.2 秒
4. **竖屏遮挡**：竖屏视频确认字幕没被平台底部 UI 盖住
5. **双语顺序**：确认上下顺序符合约定（默认译文在上）
6. **专有名词**：人名、品牌、作品名按约定处理，未约定的保留原文
7. **存疑条目标注**：听不出又猜不准的句子（ASR 严重失真），保留原文并在交付说明里
   单独列出，不要为了「看起来完整」编一句通顺的——编错了用户无从发现

## 返工的典型对应关系

| 症状 | 最可能的原因 | 修法 |
| --- | --- | --- |
| 只有一种语言 | dst.json 没覆盖全部条目 | `merge` 会硬性拦截缺条，能出文件说明是之后被改坏的，重新 merge |
| 双语但顺序反了 | 烧录漏了 `--layout source-above` | merge 默认译文在上，`synthesize` 必须配 `source-above` |
| 字幕整体偏移几秒 | 用转码后的文件做 ASR，或手改过 srt 时间码 | 用原始片重跑转写；时间码一律走 `segments.py` 搬运 |
| 中文溢出屏幕 | 译文太长 | 重译压缩，或 `--max-cjk 16` |
| 字幕显示为方块 | 字体缺中文字形 | `--font-file` 指定中文字体 |
| 烧录后画面变糊 | `--quality` 太低 | 提到 `high` 或 `ultra` |
